# პროექტის სათაური

## Kaggle-ის კონკურსის მოკლე მიმოხილვა
ეს პროექტი მუშაობს შემდეგი Kaggle-ის კონკურსის მონაცემებზე: [House Prices - Advanced Regression Techniques](https://www.kaggle.com/competitions/house-prices-advanced-regression-techniques/rules).
პროექტის მიზანია, რამდენიმე ექსპერიმენტის განხილვა და თითოეულის შეფასება. კერძოდ, არ ვეძებთ საუკეთესო მოდელებს, თუმცა ვეძებთ მიზეზ თუ რატომ არ იმუშავა ამა თუ იმ მოდელმა.

## მიდგომა პრობლემის გადასაჭრელად

მოცემულ მონაცემები სხვადასხვა ტექნიკებით გავფილტრეთ და დავამუშავეთ. დამუშავებულ მონაცემებზე გავატარეთ წრფივი რეგრესია და დავაკვირდით მიღებული შედეგის ვარიაციასა და ბაიეს. შეფასებისთვის გამოვიყენეთ სხვადასხვა მეტრიკები. უფრო დეტალურად ამის შესახებ შემდეგში ვისაუბრებ.

## რეპოზიტორიის სტრუქტურა

- **`data/`**: შეიცავს მონაცემებს. რადგან Kaggle-მა დროულად ვერ მომაწოდა მონაცემები, ხელით ჩამოვწერე.
- **`notebooks/`**: Jupyter notebook-ები, რომელშიც განვიხილეთ მონაცემთა კვლევა, წინასწარი პროცედურები და მოდელების ტესტირება.
- **`model_experiment.ipynb`**: აქ ხდება ყველა მოდელის დატრენინგება და დალოგება. ასევე, საუკეთესო მოდელის არჩევა და დარეგისტრირება.
- **`model_inference.ipynb`**: აქ საუკეთესო დარეგისტრირებული მოდელის გატესტვა ტესტ სეტზე. მიღებული answe.csv ფაილი ავტვირთე kaagle-ზე.

## Feature Engineering

### კატეგორიული ცვლადების რიცხვითში გადაყვანა
გამოყენებული მეთოდები: [One-Hot Encoding / Mean-Target Encoding]. კერძოდ, threshold=4 განსხვავებულ ცვლადიანი სვეტისთვის გამოვიყენე Mean-Target Encoding, რაც გულისხმობს სვეტის მნიშვნელობის შესაბამისებას, ამ მნიშვნელობით დაჯგუფებით და ამ ჯგუფში საშულოს დათვლით, უფრო ნაკლები ცვლადისთვის კი გამოვიყენე One-Hot Encoding, რომელიც გულისხმობს, ყველა ცვლადისთვის რაიმე ახალი სვეტის დამატებას, ორობითი ცვლადებით (რომელსაც არ ავხსნი რადგან ლექციაზე გავიარეთ). GridSearch-მა აჩვენა, რომ threshold რაც უფრო დიდია მით უფრო ზუსტია მონაცემი. თუმცა, გამოთვლის დრო მით უფრო დიდია. შესაბამისად, ამის გამო ავირჩიე 4. 

### Nan მნიშვნელობების დამუშავება
Nan მნიშვნელობის დამუშავებისთვის, მქონდა სხვადახვა მიდგომა. თუმცა იდეურად ერთი და იგივე. კერძოდ, Nan ცვლადებს ვავსებდი ტრეინ სეტის მედიანათი, საშუალოთი ან ყველაზე ხშირი ელემენტით. ეს უკანასკნელის ოპტიმალურობა იცლვებოდა იმის მიხედვით, თუ რა მოდელს ავარჩევდი. სუფთა წრფივ რეგრესიაზე, საშუალო ოპტიმალური იყო, თუმცა შემდეგ ორ მიდგომაზე (ქვემოთ ავხსნი) მედიანა საუკეთესო აღმოჩნდა. ასევე ვაგდები იმ სვეტებს, საიდაც დიდი რაოდენობით NAN ცვლადები იყო.

## Feature Selection

### გამოყენებული მიდგომები და მათი შეფასება

თავიდან, ორ სვეტს ვფილტრავდი მათი კორელაციის მიხედვით. კერძოდ, თუ ის 0.8-ზე დიდი იყო (grid-search-თ აირჩა ეს პარამეტრი), მათგან ერთ-ერთს ვაგდებდი. კერძოდ, იმას, რომელიც ნაკლებად კორილირებული იყო თარგეთან.

შემდეგ ვიყენებდი RFE. მის კოეფიციენზე უფრო ვრცლად ქვემოთ ვისაუბრებ, მოდელების აღწერისას.

## Training

### ტესტირებული მოდელები
ამ პროექტში შევამოწმე შემდეგი მოდელები: 
- [Logistic Regression]
- [Logistic Regression with transformed dataser]
- [XGBoost]
თითოეული მოდელი შეირჩა მისი სუსტი და ძლიერი მხარეების შესაბამისად.

### Hyperparameter ოპტიმიზაციის მიდგომა
ჰიპეროპტიმიზაცია განხორციელდა [GridSearchCV] ტექნიკით, სადაც მნიშვნელობა ექცეოდა nmsq (negative-mean-squered-error). ასევე, სხვა მეტრიკების შესაფასებლად ვიყენებდი [KFoldCrossValidation]-ს. გარდა მეორე მიდგომისას, სადაც უკეთესი უბრალო [CrossValidation] გამოდგა.

### მოდელების საერთო კომპონენტები

მოდელები შეიცავდნენ შემდეგ კომპონენტებს (სხვადასხვა პარამეტრებით):

1. NAHeavyFeatureRemover - აშორებს ისეთ სვეტებს სადაც დიდი რაოდენობით უცნობი ცვლადია.
2. CustomCategoricalTransformer - ახსენს კატეგორიული ცვლადების გადაყვანას ისე, როგორც ზევით არის აღწერილი.
3. SimpleImputer - ავსებს NA, ისე როგორც ზევით არის აღწერილი.
4. StandardScaler - ასკალირებს მონაცემებს და აგდებს (-1,1) შუალედში.
5. CustomCorrelationFilter - ფილტრავს კრალირებულ ცვლადებს. 
5. RFE - აგდებს არასაჭირო ცვლადებს.

### პირველი მოდელი - წრფივი რეგრესია

ამ მოდელში ზემოთ აღნიშნული კომპონენტების წყალობით, მივიღეთ კარგი R2 ქულა, კერძოდ 0.8121838571118241. თუმცა არც ისე კარგი rmse, კერძოდ 33101.50783791989. როგორც, მონაწემებზე დაკვირვებამ აჩვენა, ეს უკანასკნელი გამოწვეულია იმით, რომ გვაქვს ძალიან ბევრი ცალკე განყენებული მონაცემი, კერძოდ, ისეთი, მონაცემები, რომლებიც გაფანტულია. ანუ გვაქვს მაღალი ვარიაცია (მონაცემები მიმოფანტულია ცენტრიდან), თუმცა გვაქვს ასევე მაღალი ბაიესიც. წრფივი მოდელისთვის ხდება underfitting.

### მეორე მოდელი - წრფივი რეგრესია, outlier ების გაფილტვრით

ზემოთ დაკვირვებით მოტივირებულმა, შევიმუშავე შემდეგი მიდგომა. კერძოდ, გადავწყვიტე, მოცემული დატასეტი, outlier-ებისგან გამეფილტრა და შემდეგ დამეტრენინგებია მოდელი წრფივი რეგრესიით. ამისთვის, გამოვიყენე, ორი მიდგომა, კერძოდ iqr და zscore. iqr ვერ აღმოჩნდა, ეფექტური, რადგან ძალიან ბევრ მონაცემს ყრიდა, დარჩენილი მონაცემები კი საკმარისად კარგ prediction-ს ვერ აკეთებდნენ. ამიტომაც ავირჩიე zscore. რადგან, სატრენინგო მონაცემები წინასწარ უნდა შემეცვალა, გადავწყვიტე ჩვეულებრივი ქროსვალიდაციის გამოყენება. შედეგად მივიღე შემცირებული ქულები:

rmse: 29032.131740534693m,  r2: 0.8901135817913461,  mae: 18320.64743062243

რაც, ცხადია გაუმჯობესებაა. მსგავს მოდელს ნაკლები ვარიაცია აქვს, (ამის დასტურიც თუნდაც ისაა, რომ r2 გაიზარდა). თუმცა, ცხადია ბაიესი მაინც იქნება, რადგან მოდელი საკმარისად კომპლექსური არ არის. მოდელს კარგი ვარიაცია აქვს, თუმცა დიდი ალბათობით ზოგადი განაწილება მონაცემებისა არ არის წრფივი, რაც იწვევს იმას რომ მოდელს ცუდი ბაიესი აქვს. კვლავ გვაქვს underfiting. გვჭირდება არაწრფივი მოდელები...



### მესამე და მეოთხე მოდელი - XGBoost, Random Forest

რადგან, მონაცემთა წერტილები მიმოფანტულია, ისეთი მოდელი, რომელიც ამ წერტილებს ცალკე განიხილავს, და ცალკე მოექცევა უკეთესი იქნება. შესაბამისად განვიხილე ასეთი ორი მოდელი, თითოეულის შედეგები მოცემულია ქვემოთ:

1. **XGBoost**  rmse: 29407.320212298935,  r2: 0.8513402342796326,  mae: 16953.166015625
2. **Random Forest** rmse: 30526.03434474518,  r2: 0.8405128554502526,  mae: 18360.947600038526

ორივე შედეგი ოდნავ უკეთესი ვიდრე წინა მოდელის შედეგი. რაც ლოგიკურია, რადგან წინა მოდელის კომპლექსურობა გაზრდილია. თუმცა, უნდა აღინიშნოს, რომ შემცირებულია r2, რაც შეიძლება დაკავშირებულია იმასთან, რომ ეს მოდელები ვარიაციაზე ნაკლებად ზრუნავებ.

ასევე გასაკვირია ის ფაქტი, რომ XGBoost უკეთ მუშაობს, რადგან Random Forest-სგან განსხვავებით ეს მოდელი დიდ ყურადღებას აქცევს აუთლაიერ წერტილებს (რენდომ ფორესტი უბრალოდ ასაშუალოებს ანუ აუთლაიერ წერტილები სხვადასხვა კატეგორიაში ჩავარდებინ და დიდი ხმა ვერ ექნებათ, XGBoost კი შეეცდება ამ აუთლაიერი წერტილების გამოსწორებას). თუმცა, რეგულაციის ტექნიკებით და მცირე სიღმეზე ჩასვლით (სიღრმის ჰიპერმარამეტრი 5 აირჩა), XGBoost კარგად ფუნქციონირებს. კიდევ ერთი მიზეზი, რატომ შეიძლება იყოს ეს მოდელი უკეთესი, არის ის, რომ დაუბალანსებელ, კომპლექსური განაწილების მონაცემებზე XGBoost უკეთ მუშაობს რადგან, ყოველ იტერაციაზე სწორდება წინა იტერაციისას დაშვებული შეცდომა, რაც იწვევს ზოგადად უფრო კომპლექსური განაწილების არჩევას.


### საბოლოო მოდელის შერჩევის დასაბუთება

საუკეთესო მოდელი იყო XGBoost, რადგან ის აჩვენებდა საუკეთესო შედეგებს და ეფექტურას მუშაობდა. ზოგადად, როგორც ჩანს მონაცემების განაწილება კომპლექსურია, XGBoost კი ყველაზე ძლიერი ტექნიკაა ზემოთ აღწერილ ტექნიკებს შორის.
